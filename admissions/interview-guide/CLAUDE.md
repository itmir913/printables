# 26.8.22 수시면접대비 — 면접 지도 가이드북

## 무엇을 만드는가

2027학년도 대입 **면접** 지도를 위한 가이드북. 지도교사가 쓰는 실무 매뉴얼이자,
그대로 학생에게 공유해도 되는 자료다.

- **본문 = 유형별 면접 준비 매뉴얼.** 공통 → 서류기반 → 인적성 → 특수 → 제시문.
- **제6부 = 답변 예시 모음.** 지도교사용. 기록 → 나올 질문 → 잘못된 답 → 잘한 답 → 무엇이 갈랐나.
- **부록 = 학생 배부용.** 교사가 해당 면만 뽑아 학생에게 나눠 주는 활동지·점검표·템플릿.

화면에서 **전체 / 본문만 / 부록만** 인쇄를 고를 수 있게 한다.

## 파일 구조

원고는 편(篇)별로 나눠 두고, 묶는 일은 기계가 한다.

**빌드는 필요 없다.** `면접지도가이드북.html` 과 `문제은행.html` 을 `localhost` 로 열면 그 자리에서
조립·조판된다. 고치고 새로 고침만 하면 된다. IntelliJ 의 내장 서버로 열면 그만이다.
(`fetch` 를 쓰므로 `file://` 로는 열리지 않는다.)

`가이드북빌드.js` 와 `문제은행빌드.js` 는 **파일 하나로 건네야 할 때만** 쓰는 선택지다.
평소 작업에는 쓰지 않는다.

## 면 번호

손으로 적지 않는다. `공통.js` 가 로드 시점에 `.page` 를 세어 꼬리말과 차례에 동시에 박는다.
면을 넣거나 빼도 저절로 맞는다. 차례 항목은 `data-to="앵커id"` 로 대상을 가리킨다.

## 산출물 규칙

| 항목 | 값 |
|---|---|
| 용지 | **A4 세로(portrait)**, 210 × 297 mm |
| 인쇄 | Chrome 기준, 여백 **없음**, 배경 그래픽 **켬** |
| 본문 크기 | **12pt 기준.** 자료 어디에서도 12pt 아래로 내려가지 않는다 |
| 밀도 | 실무 매뉴얼이다. 여백보다 정보를 우선한다 |

### 넘치면 줄이지 말고 면을 나눈다

한 면에 안 들어간다고 문장을 깎지 않는다. **면을 나눈다.** 내용을 압축해서
맞추는 것은 금지다. 여백과 행간을 미세 조정하는 것까지는 허용하되,
그것으로 안 되면 면을 늘린다. 제6부는 **한 면에 예시 두 묶음**이 기준이다.

### 핵심 정리는 묶음이 끝날 때 한 면을 통째로

면마다 정리 상자를 붙이지 않는다. 앞 면 내용을 옮겨 적는 정도의 상자는
있으나 마나다. 여러 면에 걸친 묶음이 끝나는 자리에서 **한 면을 통째로 써서**
새로 서술한다. 옮겨 적기가 아니라 **가로지르는 것**을 쓴다.

`.sum` 은 면 바닥에 붙는다(`margin-top:auto`). 말머리는 **짧은 선**이다.
네모 체크박스는 "표시하라"는 뜻이므로 실제로 표시하며 쓰는 칸(`.chk`)에만
쓴다. 부록 활동지는 낱장으로 뜯어 주므로 그 면에 짧은 `.sum` 이 남아 있다.

### 문항은 원고와 조판을 가른다

기출 문항을 HTML 에 박아 넣지 않는다. `문제은행/*.md` 가 원고이고, 조판은
`문제은행.html` 이 브라우저에서 한다. 문항을 더하거나 빼고 새로 고치면 면이 저절로
다시 나뉜다. 해마다 기출을 최신화할 때 **.md 만 고친다.**

원자료는 저장소 밖(`자료/` 또는 바탕화면)에 두고, 정제한 `.md` 만 저장소에 남긴다.
정제할 때는 대학·학교·개인이 드러나는 표현을 지우고, 어미를 존댓말 질문형으로
통일한다. 앞뒤 맥락이 있어야 뜻이 통하는 조각은 버린다.

### 연도를 본문에 박지 않는다

학년도 표기는 **표지 한 줄에만** 둔다. 본문·차례·문서 제목에 넣으면 해마다
전부 고쳐야 한다.

### 학생이 쓰는 칸

부록은 학생이 손으로 쓴다. **표는 전체 너비를 쓰고**, 기입 칸은 한 줄짜리도
**12mm 이상**, 서술형은 **26mm 이상**을 준다. 좁아서 못 쓰느니 면을 늘린다.

## 흑백 인쇄 원칙 — 가장 중요

**흑백 레이저로 뽑는다. 색으로 정보를 구분하지 않는다.**

- 팔레트는 무채색만. **검정 배경, 검은 띠, 반전 글자(흰 글씨), 풀컬러 금지.**
- 부록(학생 배부용) 면은 **머리말 이중선 + 모서리 「학생 배부용」 표시**로 구분한다.
- 글자 뒤 회색 바탕은 `#f0f0f0`보다 진하게 쓰지 않는다.
- 위계는 **선의 굵기 · 테두리 모양 · 굵기(bold) · 밑줄 · 자간**으로 만든다.
- 상자 종류는 색이 아니라 **테두리 모양 + 말머리 표시**로 구분한다.
  - 일반 `.note` → 실선 좌측 굵은 막대
  - 주의 `.note.warn` → 좌측 이중선(double)
  - 도움말 `.note.tip` → 좌측 점선(dashed)
- 한글 이탤릭은 쓰지 않는다. 강조는 `<b>` 또는 `.u`(밑줄)로.

## 서식 규칙

- **Tailwind** = 면 안에서의 배치·간격. 토큰은 `면접지도가이드북.html` 의 `tailwind.config` 에 있다.
- **style.css** = 인쇄 규격과 부품(면 크기·머리말·상자·표·학생 기입칸).
- HTML 에 `style="..."` 속성을 쓰지 않는다. 한 번만 쓰는 치수도 `min-w-[40mm]` 처럼 유틸리티로.
- 서식 클래스를 새로 만들기 전에 `style.css` 에 이미 있는지 확인한다.

## 저작권 원칙

원자료에서 가져오는 것은 **사실과 패턴**뿐이다.

- 문장을 옮기지 않는다. 표현은 전부 새로 쓴다.
- 기출 문항은 유형화해서 **예시 문항을 새로 만든다.** 원문을 옮기지 않는다.
- **본문에 인용·출처 표기를 넣지 않는다.** 각주도 달지 않는다.
- 원자료와 그 텍스트 변환본은 `자료/` 에 두고 git으로 추적하지 않는다.

## 작업 순서

1. 원자료를 읽고 유형·패턴을 정리한다. — **완료**
2. 목차안을 확정받는다. — **완료**
3. 승인된 목차대로 `원고/` 를 채운다. — **완료 (88면)**
4. 브라우저 실측으로 면 넘김과 흑백 대비를 확인한다.

### 실측하는 법

`면접지도가이드북.html` 을 localhost 에서 열고, 각 `.page > .body` 의
`scrollHeight - clientHeight` 를 잰다. 0보다 크면 그 면은 넘친 것이다.
반대로 여백이 230px 넘게 남으면 그 면은 성긴 것이다. 둘 다 0이어야 한다.
